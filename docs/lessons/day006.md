## 2. What Is a Loop?

A loop is a programming structure that repeats instructions.

Robots often need to repeat operations such as:

- Reading sensors.
- Checking battery.
- Detecting obstacles.
- Monitoring position.
- Checking task status.
- Updating decisions.

Without loops, the same instructions would need to be written repeatedly.

## 3. WHILE Loop

A WHILE loop repeats while its condition remains TRUE.

Example:

```python
battery = 80

while battery > 20:
    print("Robot can continue working")
    battery = battery - 10

print("Battery is low")
```

Logic:

1. Battery starts at 80.
2. Check whether battery is greater than 20.
3. If TRUE, execute the loop.
4. Reduce battery by 10.
5. Check the condition again.
6. Stop when the condition becomes FALSE.

Battery sequence:

```text
80
70
60
50
40
30
20
```

At 20, the condition `battery > 20` becomes FALSE.

## 4. FOR Loop

A FOR loop iterates over a sequence or range.

Example:

```python
for robot_number in range(5):
    print("Checking robot", robot_number)
```

Output:

```text
0
1
2
3
4
```

`range(5)` starts at zero and stops before five.

A FOR loop is useful for checking a known collection of robots.

## 5. WHILE vs FOR

| WHILE | FOR |
|---|---|
| Repeats while a condition is TRUE | Iterates over a sequence or range |
| Useful for continuous monitoring | Useful for checking collections |
| Can continue indefinitely | Often has a defined iteration range |

Examples:

- WHILE: Monitor a robot until its task ends.
- FOR: Check all 10 robots in a warehouse.

## 6. Loops Combined with Conditions

Conceptual robot algorithm:

```text
WHILE task is active:

    Read sensors

    IF obstacle detected:
        Stop movement
        Find another route

    ELSE:
        Continue movement

    Check battery

    IF battery is low:
        Request safe task suspension
```

Loops provide repetition.

Conditions select what happens during each repetition.

Actions perform the selected operations.

## 7. Infinite Loops

Example:

```python
while True:
    print("Robot is working")
```

The condition is always TRUE.

Therefore, the loop does not stop by itself.

Infinite loops can be useful in continuous monitoring systems, but they require:

- Shutdown mechanisms.
- Cancellation support.
- Fault handling.
- Resource management.
- Appropriate timeouts.
- Independent safety mechanisms.

A software loop alone cannot guarantee physical safety.

## 8. AVYRON Example: Multiple Robots

Conceptual algorithm:

```text
WHILE AVYRON system is running:

    FOR each robot:

        Collect current status

        Check battery

        Check hardware condition

        Check active task

        Check safety status

        IF robot has a fault:
            Hold affected task
            Report the fault

        ELSE:
            Update robot availability
```

This illustrates two levels of repetition:

1. Outer loop: Keeps the system operating.
2. Inner loop: Checks each robot.

A real implementation must also handle concurrency, communication delays, real-time deadlines and failed robots.

## 9. Practical Exercise

A robot starts with 100% battery.

Every monitoring cycle:

- Battery decreases by 15%.
- The robot checks whether battery is above 30%.
- If TRUE, it continues.
- Otherwise, it stops the task and reports low battery.

## 11. Research Challenge

AVYRON controls 20 warehouse robots.

One robot suddenly stops communicating. The other 19 robots are working normally.

### Initial User Answers

1. Stop all 20 robots? No.
2. Repeatedly check the missing robot's connection? Yes.
3. Prevent checking forever? "Loop using."
4. What happens after reconnection? "Loop makes it work."

### Follow-up Research Answer

The user proposed:

"Place a loop when attempt fails up to a limit; we will disconnect it."

### Evaluation

**Research challenge: PASSED**

Improved recovery logic:

1. Detect communication loss.
2. Start a reconnection process.
3. Attempt reconnection.
4. Retry after failure.
5. Stop automatic retries after five failed attempts.
6. Mark the robot as disconnected/unavailable.
7. Record the failure.
8. Notify the operator.
9. Preserve the last known status.

If the robot reconnects later:

- Verify its identity.
- Check current battery and hardware condition.
- Check sensor and communication status.
- Reconcile its task status.
- Obtain appropriate safety authorization before resuming movement.

Reconnection does not automatically mean the robot is safe to resume.

## 12. Important Research Principle

Every retry mechanism needs:

- A defined limit.
- A timeout.
- A failure response.
- A recovery strategy.
- A record of what happened.
