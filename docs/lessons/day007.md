## 2. What Is a Function?

A function is a reusable block of instructions designed to perform a particular operation.

Imagine AVYRON controls 20 robots.

Every robot needs to check its battery.

Instead of writing the same battery-checking instructions 20 times, AVYRON can use one reusable function.

Conceptual example:

```text
FUNCTION check_battery:

    Read battery level

    Check battery condition

    Return battery status
```

The same function can be called whenever battery information is needed.

## 3. First Python Function

```python
def greet():
    print("Hello from AVYRON")

greet()
```

Explanation:

- `def` defines a function.
- `greet` is the function name.
- `()` contains optional inputs.
- `:` begins the function body.
- Indentation identifies the function instructions.
- `greet()` calls the function.

Output:

```text
Hello from AVYRON
```

Defining a function does not automatically execute it.

The function must be called.

## 4. Functions with Parameters

A function can receive information.

Example:

```python
def check_battery(battery):

    if battery >= 30:
        print("Battery sufficient")
    else:
        print("Battery low")


check_battery(80)
check_battery(15)
```

Output:

```text
Battery sufficient
Battery low
```

Important terms:

**Parameter:** A named input in the function definition.

**Argument:** An actual value supplied when the function is called.

In this example:

- `battery` is the parameter.
- `80` and `15` are arguments.

## 5. Return Values

A function can calculate something and return the result.

Example:

```python
def calculate_remaining_battery(battery, usage):

    remaining = battery - usage

    return remaining


result = calculate_remaining_battery(100, 15)

print(result)
```

Output:

```text
85
```

Explanation:

1. AVYRON supplies 100 and 15.
2. The function calculates 100 - 15.
3. `return` sends 85 back.
4. The result is stored in `result`.

## 6. print() vs return

| print() | return |
|---|---|
| Displays information | Sends a value back to the caller |
| Useful for showing output | Useful for further calculations |
| Does not automatically provide a reusable result | Provides a result to the calling code |

## 7. Functions Combined with Conditions

Example:

```python
def is_robot_ready(battery, gripper_working):

    if battery >= 30 and gripper_working:
        return True
    else:
        return False


ready = is_robot_ready(80, True)

if ready:
    print("Robot is a candidate")
else:
    print("Robot is not ready")
```

This combines:

- Functions.
- Parameters.
- Conditions.
- Return values.

The function evaluates two requirements.

Passing the requirements makes the robot a candidate, not automatically authorized for a physical task.

## 9. Problem Decomposition

A large problem can be divided into smaller functions.

Conceptual example:

```text
FUNCTION prepare_robot_for_task:

    Read sensor information

    Check battery

    Check robot capabilities

    Check physical condition

    IF all required checks pass:
        Request safety approval

    ELSE:
        Report why the robot is not ready
```

This is called problem decomposition.

It makes large systems easier to understand, test and maintain.

## 13. Research Discovery: Common Interface, Different Implementations

Different robots may have different:

- Battery capacities.
- Voltages.
- Battery chemistries.
- Battery-management systems.
- Movement systems.
- Sensors and actuators.

AVYRON can investigate a common battery-status interface while allowing hardware-specific adapters.

Conceptual architecture:

```text
AVYRON Battery Status Interface

    Humanoid Battery Adapter

    Robotic Arm Battery Adapter

    Wheeled Robot Battery Adapter
```

Possible normalized information:

```text
battery_percentage = 75%
battery_health = GOOD
estimated_remaining_runtime = 2 hours
```

The actual adapter must account for each device's hardware and measurement capabilities.

A percentage alone does not tell us everything about available energy.

This is a candidate architecture to investigate, not yet a validated AVYRON design.

## 14. Important Research Principle

Different robots can share common interfaces while using different hardware-specific implementations.

This principle may support extensibility across multiple robot embodiments.
