## 1. Objective

Understand Python sets and tuples, compare the four major Python data structures, and explore how AVYRON can organize unique, fixed and changing robot information.

## 2. Why do we need more data structures?

Imagine AVYRON receives this sensor information:

```python
sensors = ["Camera", "LiDAR", "Camera", "IMU", "LiDAR"]
```

The list contains duplicate sensor names.

If AVYRON needs only unique sensor types, a Python set is useful.

## 3. Python Sets

A set stores unique items and automatically removes duplicates.

```python
sensors = {"Camera", "LiDAR", "Camera", "IMU", "LiDAR"}

print(sensors)
```

Possible output:

```text
{"Camera", "LiDAR", "IMU"}
```

Important properties:

- Duplicate values are not stored separately.
- Sets do not guarantee item order.
- Items are not accessed using normal list indexes.
- Items can be added or removed.

### Adding an item

```python
sensors.add("GPS")
```

### Removing an item

```python
sensors.remove("IMU")
```

### Checking whether an item exists

```python
if "LiDAR" in sensors:
    print("LiDAR is available")
```

**AVYRON application:** Sets could represent unique sensor types or capability identifiers.

## 4. Python Tuples

A tuple is an ordered collection that cannot be directly changed after creation.

```python
robot_dimensions = (50, 30, 20)
```

Illustrative dimensions:

- Length = 50 cm
- Width = 30 cm
- Height = 20 cm

Access an item:

```python
print(robot_dimensions[0])
```

Output:

```text
50
```

Trying to change an item directly:

```python
robot_dimensions[0] = 60
```

This produces an error because tuples are immutable.

**AVYRON application:** Tuples can represent fixed grouped values, such as three-dimensional coordinates or fixed-size specifications. A tuple alone does not guarantee that its values are physically valid.

## 5. Four Important Python Data Structures

| Structure | Main purpose | Important properties |
|---|---|---|
| List | Collection of items | Ordered, changeable, duplicates allowed |
| Dictionary | Labelled information | Key-value pairs |
| Set | Unique items | No duplicate values, no guaranteed order |
| Tuple | Fixed collection | Ordered and immutable |

Examples:

### List

```python
robots = ["Humanoid", "Drone", "Hexapod"]
```

### Dictionary

```python
robot = {
    "name": "HEXA-R01",
    "battery": 80
}
```

### Set

```python
sensors = {"Camera", "LiDAR", "IMU"}
```

### Tuple

```python
position = (10, 20, 30)
```

## 6. Combining Data Structures for AVYRON

An illustrative hexapod robot profile:

```python
hexapod = {
    "name": "HEXA-R01",

    "sensors": {"Camera", "LiDAR", "IMU"},

    "position": (10, 20, 30),

    "legs": 6,

    "motors": 8,

    "battery": 80,

    "capabilities": ["Walking", "Obstacle Detection"]
}
```

Different structures are used for different purposes:

| Information | Structure | Reason |
|---|---|---|
| Robot identity | Dictionary | Labelled information |
| Sensors | Set | Unique sensor types |
| Position | Tuple | Fixed-size coordinates |
| Capabilities | List | Collection that can change |

These are educational examples, not the final AVYRON data schema.

## 7. Static vs Dynamic Robot Information

A robot has information that changes at different speeds.

### Relatively stable configuration information

- Robot model.
- Number of legs.
- Number of motors.
- Sensor model.
- Physical dimensions.

### Changing runtime information

- Battery level.
- Current position.
- Sensor condition.
- Current task.
- Available capabilities.

Imagine a robot has six legs, but one leg actuator becomes damaged.

Its original design has not changed, but its current movement capability may have changed.

AVYRON must distinguish:

1. What the robot was designed to have.
2. What hardware is currently working.
3. What the robot can currently do.
4. What it is verified safe to do.

This is an important architectural distinction.
